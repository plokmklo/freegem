## [2.12.0] — 2026-10-20

The research wave. A documented sweep — r/webscraping threads, the
FlareSolverr / curl_cffi / camoufox / nodriver codebases, and a 566-paper
arXiv literature sweep (docs/ANTIBOT_RESEARCH.md +
docs/antibot_papers.md) — turned into two new opt-in ladder rungs for the
walls that survived 2.11.0, plus the honest documentation of where the
line still is.

### Added

- **`tls-browser` rung** (optional `curl_cffi` dependency): the same URL
  fetched with Chrome's exact TLS/HTTP2 fingerprint — the client
  presenting browser headers IS the client whose hello the site
  fingerprints. No header overrides (a mismatched header/TLS pair is
  itself a detection signal), one cookie warm-up retry carrying the
  wall's own Set-Cookie, session discarded afterwards, `cfg.proxy`
  honored. OFF by default (`smart_fetch_tls_browser`); labeled
  `via="tls-browser"`; no CAPTCHA solving, no identity rotation.
- **`flaresolverr` rung**: an adapter for a FlareSolverr instance the
  USER runs — the community's standard self-hosted answer to managed
  challenge walls. FreeGem ships no solver and never starts one; when
  `smart_fetch_flaresolverr` holds an endpoint, the rung talks the v1
  API and labels every result `via="flaresolverr"`. Empty string (the
  default) = the rung does not exist.
- **Ladder order** is now browser-headers → tls-browser → reader →
  browser-render → flaresolverr → wayback → ai-search, with the three
  opt-in rungs dropped from the order entirely while their gates are
  closed; per-host strategy memory fronts a remembered rung only while
  its gate stays open.
- **Research documentation**: docs/ANTIBOT_RESEARCH.md (how sites stop
  agents, what passes, the ethics line, and what was shipped) and
  docs/antibot_papers.md (566-paper arXiv sweep appendix, generated by
  scripts/antibot_paper_sweep.py).

### Changed

- **NON_GOALS entry 2 reworded** to state the accurate boundary: no
  CAPTCHA solving, no identity rotation, no stealth *by default*; the
  two new rungs are explicit user choices. Same update applied to
  README "Limitations", docs/NON_GOALS.md, and the /health +
  /v1/about API surfaces.
- Live evidence from the campaign's hardest leftovers: TLS
  impersonation alone moved patreon.com from a bare 403 to a
  challenge page (solver territory) and investing.com (Akamai-class)
  stays 403 — both facts recorded in the research doc so expectations
  stay calibrated.

## [2.11.0] — 2026-10-20

The AI rung goes where the walls are: a search-grounded WALL RUNG for
pages whose fetch itself fails, and the AI-assisted scraper wired into
`research` and `crawl`.

### Added

- **AI wall rung** (`ai_scrape`): when the fetch itself fails on a
  wall-class error (403/429/5xx/timeout — never our own SSRF/cap
  refusals), one search-grounded model call is asked for the page's main
  content, with a cited source URL. The answer ships only if it clears
  the honesty floors: 80+ chars, no self-admitted non-answer. Wins are
  labeled `via="ai-wall-rescue"` — an AI-mediated read, never presented
  as a verbatim fetch — and never enter any cache. New `search` seam
  (plus `default_search`, bounded like the ladder's ai-search rung) makes
  the whole rung hermetically testable and campaign-throttleable.
- **`research --ai`**: pages fetch through `ai_scrape` — gated content
  rescue for poor extractions plus the wall rung for fetch-failed pages.
  Default stays byte-identical (`ai_extract="never"`); AI views are never
  cached, so the shared-cache contract (#21) is untouched.
- **`crawl run --ai-rescue`**: the crawler's default (no-schema) records
  get the same gated rescue when their extraction grades below `ok`
  (`ai_rescued`/`ai_rescue_note` in the record). Fetch failures stay the
  resilient fetcher's business — a frontier never turns into unbounded
  model calls on dead URLs.
- **`rescue_text`**: the scrape rung's gate, factored out as a public
  helper for callers that hold extracted text from another pipeline.
- **Campaign deep phase widened**: JS-heavy categories (js-spa, media,
  bot-walled) join the always-mode population; a new wall phase
  (`ai_wall_phase.py`) re-attempts every phase-A failure through the wall
  rung with one grounded verify question per accepted read.

### Documentation

- README now documents the AI wall rescue layer (honesty floors,
  `via="ai-wall-rescue"` labeling, never cached), `research --ai`, and the
  crawler's `--ai-rescue` flag with its `ai_rescued`/`ai_rescue_note`
  record fields.

## [2.10.0] — 2026-10-19

AI-assisted web smart scraping: the LLM joins the extraction pipeline as a
gated, labeled rescue rung — on request, never silently.

### Added

- **`freegem.ai_scrape`**: a library layer over `scrape_page`. The
  deterministic pipeline (smart-fetch ladder included) always runs first;
  its text is graded by `extraction_quality`; only when the grade is poor
  (`nav_only` / `empty`) — or the caller forces `ai_extract="always"` —
  does the model see the page, with one tightly scoped job: return the
  page's main readable content in the page's own words. The rescue is
  GATED: the model's text must grade strictly better than the heuristic
  text (or be 10% longer at equal grade against a substantial original)
  or it is discarded and the heuristic result ships with an honest note.
  A page the heuristic pipeline already read well costs zero model calls.
- **CLI**: `freegem scrape URL --ai` (auto rescue), `--ai-extract
  auto|always|never`, and `--schema '{"field":"type",...}'` for
  schema-validated structured fields (via `llm_extract`, repair-once).
  `--ask` composes: the answer grounds on the shipped (possibly rescued)
  text. AI notes go to stderr in text mode and ride in the record under
  `notes` in `--format jsonl`; batch mode (`scrape URL1 URL2 ... --ai`)
  runs the same path through the bounded pool with per-URL failure
  capture.
- **Provenance discipline**: `via` reports how the shipped text was
  actually obtained (`ai-extract` when the model's text won the gate);
  `ai_used` is true only when the model contributed; AI views are NEVER
  written to the shared research cache (it holds heuristic full-page
  extractions, per the #21 contract). Page content reaches the model
  defused and framed in the same untrusted-content markers the `--ask`
  path uses. Per-host memory
  (`$FREEGEM_CACHE_DIR/ai_scrape_memory.json`) records which pipeline
  last read each host — advisory notes only, the heuristic still runs
  first everywhere.
- **`ai_scrape_many`**: bounded-pool batch with the same pool discipline
  as `scrape_many` (config ceiling clamp, per-host locks, ordered
  results, per-URL failures recorded instead of killing the batch).
- **tests**: 49 hermetic tests (fake completion seam, loopback server,
  DNS/dial fakes): the zero-cost contract, gate decisions, honest notes
  for model refusals / rate limits / unparseable schema answers, memory
  round-trips, cache non-pollution, batch order, and CLI wiring for
  text / jsonl / batch / `--ask` / `--schema` paths.

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **stream-interrupted recovery**: when `freegem ask` streaming fails after
  partial output (e.g. "Gemini rewrote an already-streamed block"), the CLI
  now replays the request via the non-streaming path and prints the
  complete answer with an `[complete reply follows]` separator, instead of
  erroring out with a half-streamed reply. Five of 1,525 benchmark runs
  hit this window; all now recover.

### Added

- **`freegem scrape --ai-clean` / config `"smart_fetch_ai_clean"`** — one
  bounded Gemini pass over an already-fetched page's extracted text that
  returns the page's main readable content (navigation, cookie banners,
  subscription prompts, and related-link walls dropped). OFF by default;
  single-URL text/markdown only; mutually exclusive with `--ask`; labeled
  in the output (`ai-clean view`, an HTML comment in markdown mode); never
  written to the shared fetch cache (#21 discipline); a model answer that
  admits it could not read the page — or says exactly `NO MAIN CONTENT` —
  is an honest failure, not content. The wait is capped (30 s) and sized
  to the caller's remaining budget; a refusal-shaped short answer
  classifies as "no main content" before the length gate can mislabel it.
  (Smoke-matrix finding, fixed pre-merge: the `--ai-clean` flag itself now
  turns the config gate ON for the run — without that wiring the flag
  could never leave the "disabled" state for anyone who did not also edit
  the config file.)
- **watch state management (#55)**: `freegem watch --list` (every stored
  watch; corrupt state files are listed first, not hidden),
  `--forget URL`, `--forget-all`, and pre-check sweeps `--max-age DUR`
  (intervals now accept `d` days) and `--max-entries N` (evicts the
  oldest-checked). Corrupt entries count as never-checked so they are
  always first out under either sweep.
- **OpenAI-client compatibility round** (grounded in what Reddit's bridge
  users actually send these tools): legacy `POST /v1/completions` (one
  prompt, non-streaming, honest 400s for stream/multi-prompt),
  `POST /v1/embeddings` answering an honest 501 with the reason and the
  alternative instead of the chat catch-all's baffling 400, an honest 400
  for `n > 1` (the session makes one choice), and config
  `"model_aliases"` (JSON object or compact `alias=model` string) to pin
  where hardcoded client model names route. Unknown names keep falling
  back to `default_model` (Codex CLI compat).
- **`freegem scrape --guard` / config `"guard": true`** — opt into the SSRF guard
  (scheme allowlist + public-IP checks + pinned dial + redirect re-checks) as a
  feature instead of a default gate. Plain `scrape` fetches and hands text to
  the caller/AI (user directive 2026-10-17). `serve`/`mcp` force it ON.

### Changed

- **validation loosened to opt-in on exactly one surface**: `freegem scrape`
  no longer pre-refuses targets by default (the operator typed them). Every
  other surface — `serve`, `mcp`, `research`, `verify --discover`,
  `ask --search`, `crawl`, `watch` — forces the guard ON (a prompt-injected
  agent cannot read local files or probe the internal network through them).

- **watch (#52) one failed poll inside an interval loop is a recorded line
  and a retry on the next tick — not a crash.** A `--once` poll that fails
  still exits `1`, now with the honest line (`fetch failed: ... no verdict
  this poll; the stored baseline is kept`) on stdout instead of only an
  error on stderr.
- **watch (#53) a poll that answers with junk records no verdict and keeps
  the baseline**: an empty extraction (JS shell, blank soft-200) or a
  bot-challenge page never becomes a baseline and never overwrites one;
  diffing resumes when the real page returns. Short-but-real pages (a
  number, a one-line status) are still legitimate baselines.
- **smart-fetch (#57) the challenge gate decides by phrase density, not
  length alone**: the old rule failed open past 800 chars, so a rendered
  JS interstitial with a long explanatory body passed as content, got
  remembered as a browser-render WIN, and poisoned that host's ladder
  position. A long page with 3+ challenge-marker hits in the head window
  is a wall; a long article that mentions a captcha once is content.
- **smart-fetch (#58) browser renders are daemon-threaded and capped at
  two concurrent Chromium processes.** The old ThreadPoolExecutor's
  non-daemon threads let a wedged `sync_playwright()` block PROCESS EXIT,
  and a 16-worker batch could stack 16 browsers unbounded. A timed-out
  render's thread is still abandoned (threads cannot be killed) — it can
  no longer block exit, and the slot cap bounds the orphan ceiling.
- **smart-fetch (#59) expensive rungs size their wait to the ladder's
  remaining wall-clock budget**, and a rung entered with under a second of
  budget is SKIPPED with an honest message instead of stacking its full
  20–30 s on top of an exhausted ladder.
- **smart-fetch (#60) gated-off rungs leave the ladder entirely**: with
  `smart_fetch_browser_render=false` (the default) or `smart_fetch_ai=false`
  the rung is dropped from the walk and its slot is not spent; a remembered
  winning strategy cannot front-rank while its gate is closed, and a config
  flip no longer needs memory invalidation.
- **smart-fetch (#61) the browser-render rung renders in two phases**: a
  short `networkidle` attempt (quiet pages settle fast and get the best
  render), then — only when the network never goes quiet (SPA
  long-polling, websockets) — a `domcontentloaded` attempt with a settle
  beat for SPA hydration. The old single `networkidle` wait timed out
  hardest on exactly the JS-heavy pages the rung exists for. Both attempts
  are recorded honestly on total failure.

### Fixed

- **watch (#54) concurrent saves can no longer tear a state file**: the
  atomic-write temp name is UNIQUE per write (mkstemp + `os.replace`), not
  a fixed `<name>.tmp` two writers of the same URL shared — the old
  interleaving produced half files that `load` read as corrupt and
  silently reset to fresh baselines. A failed save removes its temp file,
  and the one Windows-specific flavor of failure — a transient
  `PermissionError` when the target is mid-rename under a concurrent
  writer — is retried briefly instead of crashing a watch loop.
- **watch (#56) the stored simhash must be what the stored text actually
  hashes to**: `text_hash` gates the verdict, but the simhash drives the
  reported distance, and a tampered or stale simhash used to sail through
  load and skew every report. Either mismatch loads as None (fresh
  baseline).
- **scraper (#62) UNC / network-share targets are refused by shape** —
  `\\host\share`, the `//host/share` spelling, and the `\\?\UNC\...`
  extended form raise an honest error BEFORE any `os.path.exists` probe,
  which would otherwise dial the share: "reading" one is an SMB network
  fetch wearing a disk-read costume, breaking the local-file contract in
  both directions at once.
- **scraper (#63) the guarded opener is HAND-BUILT**: stdlib
  `build_opener` silently installed `FTPHandler`, `FileHandler`,
  `DataHandler`, and `UnknownHandler` — none of which run the pinned
  dial — so `scrape ftp://169.254.169.254/` could reach the cloud metadata
  service with NO resolve-check and NO pin in BOTH guard modes. The manual
  opener installs only audited http/https handlers (plus redirect checks
  and the optional cookie processor); every other scheme fails with an
  honest error before any packet leaves (the scheme gate also gives a
  clear refusal message instead of an unhandled-scheme traceback).
- **scraper (#64) the IP-pinning boundary is documented as ALWAYS ON**: it
  lives inside the opener's pinned handlers in both guard modes and does
  not depend on any config flag; the `guard` setting changes only whether
  the URL-policy pre-flight runs.
- **Server**: `Sec-Fetch-Site: cross-site` POSTs are refused only when the
  request does not carry a loopback `Origin`. A local UI on another port of
  this machine (`localhost:3000` -> this server) is cross-site by origin
  rules and works again; cross-site with a foreign, `null`, lookalike, or
  missing `Origin` stays a 403 before generate() runs.
- **Server**: the kernel accept backlog is 128 (socketserver's silent
  default is 5). A 64-client burst against the concurrency cap no longer
  has connections reset by the operating system at the accept queue;
  saturation is still answered by the server's own 503 shed.
- **Docs**: install instructions use the GitHub URL — the package is not on
  PyPI, and the previous `pip install freegem` line 404s. SECURITY.md's
  supported version is now 2.9.x, and it documents the POST gates and the
  load-shedding path.

## [2.9.3] — 2026-10-18

### Fixed

- **local file scraping is dead no more (#50)**: `freegem scrape` refused
  every local target — a Windows drive path (`C:\...`) was parsed as URL
  scheme `c` ("refusing scheme 'c'"), and an explicit `file:` URI was
  refused outright, killing the documented quota-free local-batch path on
  Windows. Local targets are now routed to a disk read through the SAME
  extraction pipeline as the wire path: existing paths (POSIX and Windows),
  drive-letter paths even when missing (honest "local file not found"
  instead of a scheme refusal), `file:` URIs (`file:///C:/...`, and the
  two-slash `file://C:/...` habit normalizes), plus the two-slash drive
  form. The local path skips robots.txt (an HTTP concept) and the cache (a
  disk read needs no de-dup); the 100 MB body cap and the extraction
  pipeline are exactly the wire path's.
- **the loosening loosens exactly one gate**: only the CLI — where the
  operator typed the target — enables local reads (`allow_local=True`).
  MCP `web_scrape` and server tool surfaces keep refusing local targets so
  a prompt-injected agent cannot read arbitrary local files through them,
  and `http://169.254.169.254/` stays refused even with local reads on
  (pinned by test). `file://server/share` (a UNC/SMB fetch in disguise)
  stays refused, and classic MS-DOS device names (`con`, `nul`, `com1`,
  ...) are refused as targets on Windows — `con` would hang the read.
- **version alignment**: `pyproject.toml` had drifted (`2.9.0`) behind
  `freegem.__version__` (`2.9.2`); both now read 2.9.3.

### Fixed

- **research cache**: `ResearchCache` is now thread-safe. `put()` is a

## [2.9.0] — 2026-10-12

Release gate, browser/proxy security, bounded background jobs, and a
smarter, limit-free scraping stack.

### Bug fixes (external review round 2)

- **`gemini.RateLimitError`** (new, subclasses `BridgeError`): the
  ambiguous empty-200 answer — in practice the anonymous-tier rate limit
  or a login wall — is now a typed, catchable error on both the
  non-streaming and streaming paths, retried with backoff inside the
  module and re-raised as itself (never wrapped into a generic
  `BridgeError`) after the attempts run out. A silent empty stream no
  longer looks like a successful answer.
- **Backoff honors Retry-After**: the retry cap 30s → 120s. Truncating a
  server's explicit "come back in 90s" to 30s just bought another 429;
  server-provided windows now pass through intact up to the 2-minute
  safety bound.
- **`extraction_quality` floor 200 → 80 chars + prose-ratio gate**:
  genuinely short pages (dictionary entries, one-paragraph notices, API
  error bodies) were mislabeled `nav_only`; text that clears the 80-char
  floor but is mostly digits/punctuation/separator chrome (status dumps,
  JSON payloads, copyright walls) is now still labeled `nav_only`.
- **`crawl run --model` fixed**: the nested crawl subparsers were built
  from a parent that lacked the global flags, so `freegem crawl run
  --model X` failed with "unrecognized arguments" — the one placement
  users actually type. `crawl_common` now carries the common parent
  (plan/run; `status` needs no model).

### Smart fetching and scraping

- **`freegem/smart_fetch.py`** (new): a fallback ladder for pages that
  refuse the first, honest request. After a 403/405/401/407/429/5xx,
  timeout, reset — or a 200 that extracts ZERO readable text (a JS shell
  is not a success) — freegem walks legitimate read paths in order —
  a browser-identifying retry, the r.jina.ai public reader (optional
  `reader_api_key` config for datacenter IPs), the Internet Archive's
  closest snapshot, and (last, labeled `via="ai-search"`) the bridge's own
  Gemini search, which is attempted anonymously where the network allows
  and whose "I could not access that page" replies are recorded as honest
  failures, never presented as content — and REMEMBERS which path worked
  per host (`~/.cache/freegem/smart_fetch_memory.json`), so repeat
  fetches go straight to the working strategy. No CAPTCHA is ever solved
  and no challenge answered: a bot wall stays unread, and the failure
  taxonomy names every attempted path and its exact refusal.
- **Body cap 5 MB → 100 MB** (wire AND decompressed, still enforced while
  reading and while gunzipping): huge homepages (cnn.com) and big
  reference pages died at 5 MB with a cap error instead of being read.
- **MediaWiki full-parse adapter**: wiki articles now come through
  `action=parse` (complete rendered article, tables included) instead of
  the extract-capped `prop=extracts` API — the gap that made reader
  services look "better" on long Wikipedia pages (87k vs 495k chars).
  The plain-text extracts API (now with `exlimit=1`,
  `exsectionformat=plain`) remains the fallback.
- **Default `max_chars` 20,000 → 50,000**: long pages (HN threads, API
  references) were truncated before the interesting part.
- **`--ask` reads the whole page**: question mode auto-raises the
  character budget to the 200k hard limit when no explicit `--max-chars`
  was given — a question against a truncated page guarantees a useless
  answer. Explicit budgets are always respected.
- **Batch scrape**: `freegem scrape URL1 URL2 URL3 --format jsonl` —
  bounded parallel pool (per-host locks), one JSON object per line with
  the result or the honest error, per-URL failures never kill the run,
  exit 1 only when nothing succeeded. Text mode labels each page with
  title/chars/via.
- **Shared fetch cache**: `scrape_page()` accepts the research cache, so
  one-shot scrapes stop re-hitting URLs fetched minutes ago. CLI flags
  `--no-cache` / `--refresh` / `--cache-ttl` (default on, 1800s TTL).

### Security

- **Untrusted-marker escape closed** (`web_scraper.py`, `web_research.py`):
  page text, titles, and link labels are defused before wrapping — a page
  carrying the literal `[END UNTRUSTED WEB CONTENT]` string could close the
  trust wrapper early and inject the rest of its content as prompt-level
  instruction. Markers inside untrusted payloads now read
  `[untrusted-content marker removed]`.
- **Image fetch capped** (`multimodal.py`): `fetch_image_bytes` streams in
  1 MiB blocks under a 25 MB hard cap and refuses an over-large declared
  Content-Length up front; the old unbounded `response.read()` let any
  `image_url` in a request body exhaust RAM (unauthenticated).
- **CGNAT and site-local refused** (`ssrf.py`, `multimodal.py`): the guard
  now blocks `100.64.0.0/10` (RFC 6598) and `fec0::/10` explicitly — stdlib
  `ipaddress` classifies neither as private on CPython 3.12. One shared
  `ip_is_nonpublic()` is now the single source of truth for the pinned
  handlers and the image pre-check.
- **Redirect hops check credentials** (`ssrf.py`): `SafeRedirect` now
  refuses redirect targets with embedded `user:pass@` — the first URL was
  checked, the redirect was the loophole.
- **Chunked bodies capped cumulatively** (`server.py`): a stream of
  under-cap chunks accumulated unbounded RAM before the post-join check;
  the total is now refused the moment it would exceed the limit.
- **Server counters under a lock** (`metrics.py`): `requests_total`,
  `by_status`, and the upstream-retry counter are read-modify-write from
  worker threads — `+=` is not atomic under the GIL, so lock-free counting
  silently lost updates.

- **Evidence verification at map/reduce scale** (`web_research.py`): the
  reduce pass only ever saw paraphrased notes, so verbatim-quote
  verification silently degraded to 0 verified exactly when material
  crossed the 40k single-pass budget. The map pass now nominates verbatim
  quote candidates from the raw chunks, they are verified deterministically
  against the chunk they came from, and the reduce pass quotes the
  pre-verified pool (any pool quote re-verifies page-level; anything else
  still fails honestly).
- **Skipped-page accounting** (`web_research.py`, `claim_verify.py`):
  budget-skipped pages (ok=False, skipped="max_pages") fell into neither

  `pages_ok + pages_failed + pages_skipped == urls_requested`; the text

- **Windows cp1252 crash** (`cli.py`): `main()` forces stdout/stderr to

### Changed — fetch-for-readability policy (no robots.txt, by design)

- **robots.txt is never fetched and never consulted anywhere in freegem.**
  A robots.txt is attacker-controlled text served from the same origin as
  the pages being read; parsing it (or, worse, feeding it to a model) is a
  documented prompt-injection and policy-poisoning vector — other scrapers
  and AI agents have been steered by lines planted in robots.txt. The
  crawler, the campaign, `scrape_page`, the MediaWiki adapter, and URL
  discovery all dropped the gate. The legacy behavior stays available as an
  explicit opt-in (`scrape_page(..., ignore_robots=False)`, CLI
  `freegem scrape --respect-robots`). Politeness is per-host pacing; attacks
  (auth bypass, wall cracking, hammering) remain out of scope.
- **Escalation ladder** (`crawler/resilient.py`, new): every campaign/crawl
  fetch goes through `fetch_resilient` — honest freegem identity first, then
  browser-grade header profiles (Chrome, then Firefox) for 403/406 walls,
  `Retry-After`-honoring 429 waits (bailing out early on IP-keyed rate
  limits — later `--retry-failed` passes catch the window reset), timeout
  doubling for slow origins, origin-root fallback for dead paths (404/410),
  https↔http and www↔apex swaps for broken transports, and — ONLY for broken
  certificate chains — one TLS-relaxed retry flagged `tls_unverified`.
  401/402/451 are never bypassed. A `HostPacer` spaces same-host requests
  across threads and extends the gap on 429.
- **100 MB page reads** (`crawler/fetch.py`, `hardening.py`): the body cap
  went from 2–5 MB to 100 MB (wire AND decompressed, bomb-safe), with
  streaming reads that SPILL to disk past 16 MB (`spill_bytes`,
  `FetchOutcome.body_path`) so a huge page costs disk, not RAM; spill files

  cnn.com, big Wikipedia pages, and chosun.com front pages now read fully.
- **Important-only distillation** (`crawler/distill.py`, new): pages ≥ 2 MB

## [2.5.0] — 2026-10-11

### Added

- **Claim verification (`freegem verify` CLI, `web_verify` MCP tool)** —
  judge a list of claims (1–8) against fetched sources and get, per claim,
  exactly one machine-checked status: `supported`, `partially_supported`,
  `contradicted`, `not_found`, or `source_unavailable`. "The source
  contradicts the claim" is finally distinct from "the sources did not
  contain enough evidence", and a failed fetch is never evidence of falsity.
  Sources use the same guarded, robots-aware, budget-capped fetch machinery
  as research, and fetches share the same local cache.
- **Evidence passages with Source / Location / Retrieved** — every status
  quote is checked verbatim against the text actually fetched (flagged
  verified or `UNVERIFIED`, never silently deleted), each verified quote
  gets a deterministic Location computed by finding it inside the source's
  sectioned text ("Introduction", "§ History", "para 7" — the model never
  asserts where evidence lives), and a Retrieved date from the fetch
  metadata. Text output follows the documented Claim / Status / Evidence /
  Source / Location / Retrieved shape; markdown and JSON render the same
  data.
- **Status schema enforcement** — the model's verdicts are validated
  against the closed vocabulary: unknown statuses become `not_found`, a
  "supported" verdict without quotable evidence is downgraded with a note,
  missing verdicts are reported as `not_found` ("no verdict was returned"),
  evidence citing unloaded sources is dropped, and every repair is counted
  and surfaced (`schema_repairs` in the metrics). When all sources are
  dead, no model call happens at all: every claim is `source_unavailable`
  by construction. When Gemini is unavailable, verdicts are left unjudged
  with the raw material attached — never fabricated.
- **Optional URL discovery** — with `discover=True` and no URLs, candidate
  pages come from a supported search API instead of the user: the
  Wikimedia API portal (api.wikimedia.org) for Wikimedia wikis and the
  site's own OpenSearch API for other MediaWiki hosts (config
  `discover_wiki`). Every discovery request is robots-checked like any
  other fetch — Wikimedia's robots.txt disallows its `/w/` search APIs to
  generic agents, so the portal host is used rather than working around a
  rule — and discovery is one bounded API call, never a crawl. If robots
  refuses, discovery refuses with an explicit message.
- **Metrics layer (`freegem/metrics.py`)** — per-run request IDs, stage
  timings (discover / fetch / generate / parse), and counters (fetches,
  cache hits, evidence offered/verified, schema repairs) attached to
  verify output and surfaced in JSON `meta.metrics`; process-wide
  `ServerMetrics` for the HTTP face with a bounded latency window and
  p50/p95/p99 (nearest-rank), response-status counts, queue-refusal
  counts, upstream retry counters, and RSS memory — rendered by the new
  **`GET /metrics`** endpoint (aggregates only). POST responses carry an
  `X-Request-Id` header.
- **Hardening fixture corpus (`tests/fixtures/verify/`)** — malformed-HTML
  pages (void-element jam, nested unclosed markup) run through the real
  extractor and must degrade honestly; a prompt-injection page that
  fabricates verdicts ("Status: Supported") must never move the
  deterministic status machinery; changed-Gemini-response fixtures pin the
  claims-block parser against unknown statuses, missing evidence,
  duplicate/out-of-range entries, and a second fence; and
  `claim_set.json` is an executable benchmark contract pairing claims,
  source text, a model answer, and the expected statuses, quote
  verification, and Locations.

### Fixed

- A `supported`/`partially_supported`/`contradicted` verdict whose every
  quote was dropped (evidence cited an unloaded source) is now downgraded
  to `not_found` with a note — the evidence rule holds after drops, not
  only at parse time.

## [2.3.0] — 2026-10-11

### Performance

- **Connection reuse for Gemini calls** — non-streaming requests now go
  through the same pooled `httpx.Client` as streaming (when httpx is
  installed), saving a fresh TLS handshake per request. Clients are keyed by
  (proxy, timeout) so a config change can never silently ride an old client.
- **Concurrent research fetching** — pages from different sites are fetched
  in parallel by a bounded worker pool (`research_concurrency`, default 3,
  CLI `--fetch-concurrency`, MCP `fetch_concurrency`; hard cap 8). Fetches to
  the same host serialize via per-host locks; budget decisions stay strictly
  in request order and total-budget accounting is unchanged.
- **robots.txt cache** — per-origin cache with a TTL (default 600 s,
  `robots_cache_ttl_sec`) and conditional revalidation via ETag /
  Last-Modified, so research over N pages of one site pays for robots.txt
  once instead of N times. Refusal semantics unchanged; a network failure
  during revalidation serves the last known rules.
- **Time-to-first-token logging** — both streaming API faces log `ttft` per
  request, so buffering or upstream slowness shows up in the log.

### Added

- **MediaWiki source adapter** — Wikipedia/Wikimedia article URLs are fetched
  through the site's own Action API (`prop=extracts&explaintext`) instead of
  scraping HTML, producing clean article text with no navigation chrome.
  Same SSRF guard, robots.txt honored for the API URL (never bypassed), same
  size caps; per-source metadata records `via: mediawiki-api`.
- **Extraction-quality indicators** — every research source is labeled
  `ok` / `nav_only` / `empty` in the JSON output (and flagged in the text
  tables), so a caller can tell a real article from a navigation stub.
- **Optional bounded request queue** — `request_queue_wait_sec > 0` lets a
  burst wait briefly for a free slot instead of getting an immediate 503;
  the in-flight bound (active + queued) stays hard. Default `0` keeps the
  refuse-fast behavior. Shed responses now carry a `Retry-After: 2` header.

### Changed

- README rewritten: positioning, per-face tables, structured-adapter and
  quality documentation; GitHub About description and repository topics
  updated separately from the README.
- Config template documents the three new fields.
- 29 new offline tests (395 total): robots cache, MediaWiki adapter,
  quality labels, concurrent collection (order / budgets / per-host
  serialization), admission queue, pooled-client keying.

### Added

- **`freegem research` CLI command and `web_research` MCP tool** — multi-source
  cited research built on the scraper. Give it a question and 2-10 URLs; it
  fetches each page with the same SSRF/robots/5 MB machinery as

## [2.1.1] — 2026-10-10

### Security

- **Server: cross-site POSTs are refused before any work happens.** A browser
  can send a "simple" cross-origin POST (`Content-Type: text/plain`) without a
  CORS preflight, and such requests previously ran to completion — including
  the Gemini call on the user's session. Two independent layers now gate every
  POST: (1) any `Origin` header that is not this machine's own loopback gets a
  403 (`Origin: null` included; a missing Origin — curl, SDKs — still works),
  and (2) the body must be `Content-Type: application/json` (415 otherwise),
  which browsers cannot attach without a preflight. Charset suffixes
  (`application/json; charset=utf-8`) are accepted.

### Fixed

- **Server: hard cap on concurrent request threads** (`ThreadedServer`,
  default 32, configurable via `max_concurrent_requests=`). Every in-flight
  request holds a worker for up to the 65 s handler timeout; beyond the cap,
  new connections get an immediate 503 written on the raw socket before any
  thread is spawned, instead of growing the thread count without bound.
- **Retries now back off exponentially and honor `Retry-After`.** The fixed
  `retry_delay_sec` sleep became `delay * 2^(attempt-1)`, capped at 30 s; when
  the upstream sends `Retry-After` (delay-seconds or HTTP-date), the longer of
  the two wins, capped the same way. Applies to both `generate()` and
  `generate_stream()`.
- **One shared SSLContext everywhere.** `build_guarded_opener()` accepts a
  caller-supplied context, and every guarded fetch (scraper, robots.txt,
  image fetcher) now passes the project's cached `gemini._ssl_ctx()` instead
  of building a fresh context — and re-parsing the CA bundle — per request.
- **CI: the `mcp` extra is actually tested.** A new `smoke-mcp` job installs
  `.[mcp]`, builds the FastMCP server, and runs the tool-dispatch tests with
  the real `mcp` package present, so a broken MCP face can no longer hide
  behind "extra missing, skipped".

### Added

- **Daily breakage canary** (`.github/workflows/canary.yml`, cron 07:23 UTC).
  This project talks to an unversioned web endpoint and live sites, so the
  likely failure is an upstream change, not a commit. The canary runs without
  credentials: `freegem doctor`, an end-to-end scrape of a stable page, a
  robots.txt refusal, and two SSRF-refusal probes (loopback and the cloud
  metadata address). Red canary = something upstream moved.
- **26 new tests** (330 total): cross-origin/Content-Type refusals assert the
  Gemini call is never reached, thread-cap shed-load behavior over a real
  socket, exponential backoff curves and Retry-After parsing (both RFC forms),
  and the shared-SSLContext invariant on the guarded opener.

## [2.0.0] — 2026-10-10

Rebuild of the upstream `gemini-web2api` design into a maintainable package.
See [Credits](README.md#credits): the Gemini Web protocol knowledge, the model
registry, the multimodal upload flow, and the cookie-sync extension all come
from that project.

### Added

- **Three faces, one command.** `freegem serve` (OpenAI + Google-native HTTP
  API), `freegem mcp` (agent tools), and a one-shot CLI (`ask`, `models`,
  `doctor`) all run through one entry point.
- **`gemini_advisor`** MCP tool: a structured second opinion returned as
  Recommendation / Options / Tradeoffs / Risks / What would change my mind.
- **`doctor`** command: reports session state, cookie parse result, XSRF
  presence, connectivity, and model resolution — without spending a request.
- **177 tests** covering config, model resolution, the protocol client, prompt
  translation, HTTP endpoints, the CLI, and MCP dispatch. No test touches the
  network, so CI needs no credentials.
- Docker image and `docker-compose.yml` with an optional MCP profile. The image
  carries no credentials; the session is mounted read-only at runtime.
- `docs/ARCHITECTURE.md` recording the layering rules and the reasoning behind
  each boundary.
- `CONTRIBUTING.md`, `SECURITY.md`, and GitHub issue/PR templates.
- Editable install with full type hints (`py.typed`) and strict `mypy`.

### Changed

- **Configuration is immutable.** `BridgeConfig` is a frozen dataclass. The
  upstream single-file version used a module-global mutable dict, which under a
  threaded server is a data race: one request's override can be observed by
  another mid-flight. A Cloudflare Workers port of the same project shipped
  that exact bug as cookie cross-contamination between concurrent requests.
- **Build-tag refresh actually works.** Upstream matched only
  `boq_assistant-bard-web-server_*` and *silently* gave up when Google moved to
  `boq_gemini-web-uiserver_*`, so the auto-update appeared functional while
  doing nothing. Both patterns are matched, newer format preferred, and an
  empty result is logged instead of passing for success.
- **Default bind is loopback** (`127.0.0.1`), not `0.0.0.0`. Since this project
  has no authentication layer, an open bind would expose the Google session to
  the whole network.
- **Authentication removed entirely.** There is no `api_keys` field and no
  bearer-token path. Access control is the loopback bind; a test asserts the
  field does not come back.
- **SSE terminates correctly.** The OpenAI `[DONE]` sentinel is emitted as a
  bare `data: [DONE]` line (upstream wrapped it in JSON, so no OpenAI client
  detected end-of-stream), and the socket is closed, since an SSE response has
  no `Content-Length` and clients otherwise block waiting for bytes that never
  arrive.
- **Function-call parsing handles nested arguments.** Upstream's non-greedy
  `[^`]*?}` regex stopped at the first `}`, truncating
  `{"city":"Lima","opts":{...}}` and dropping the call. Brace balancing now
  respects string literals, and two consecutive calls are both parsed instead
  of the second leaking into the reply text.
- **Stream corruption aborts instead of hiding.** If a snapshot stops extending
  already-emitted text, the stream raises rather than silently rewriting what
  the client has rendered.
- **A half-written cookie file no longer drops the session.** On parse failure
  the last good value is kept rather than degrading to anonymous.
- `gemini-web2api` → `freegem` throughout: package, command, imports, config
  paths, and the `GEMINI_BRIDGE_CONFIG` → `FREEGEM_CONFIG` environment variable.

### Removed

- Dead `GEMINI_BRIDGE_HOST` / `GEMINI_BRIDGE_PORT` environment variables, which
  were set by the Docker files and never read. Host comes from `--host` or
  `config.json` only.

### Fixed

- SSE hang on the Google-native stream (`curl -N` blocked indefinitely after
  the final chunk).
- Tool-call response missing `tool_calls` when the model emitted a fence
  without surrounding prose.
- Unknown model names falling back silently without any log line, making a
  typo indistinguishable from a routing decision.

### Fixed

- **Malformed client input returned HTTP 500 with a traceback instead of a
  protocol error.** Fuzzing the published package found six client-triggerable
  500s: `messages[].content` as an int or dict raised inside `" ".join`,
  `systemInstruction` as a string raised on `.get`, `toolConfig` and
  `toolCall.function` as non-dicts raised AttributeError, and
  `functionDeclarations` as a string silently dropped every tool while still
  returning 200. All now coerce or skip and return a valid response. A
  malformed request is the client's problem and should not read as a server
  fault.
- **A client that declared `Content-Length: 99999` and sent 36 bytes hung a
  worker thread forever.** No socket timeout was set, so `rfile.read()`
  blocked indefinitely; under `ThreadingMixIn` each such connection
  permanently consumed a thread. Requests now time out after 65s and return
  HTTP 408 with a JSON body. Detected live: the connection used to block
  indefinitely with no response at all.
- **`"name": null` in a model-emitted tool call was forwarded as a null name.**
  OpenAI's schema requires a string, so a strict client rejected the entire
  completion over one malformed call. Blocks without a string name are now
  dropped, and `"args": null` is coerced to `{}` so the emitted
  `functionCall` part is always schema-valid.
- **`tools` sent as an unwrapped dict dropped every declaration.** Google's
  schema says an array; a dict-shaped `tools` meant the client sent one group
  unwrapped, and it was silently discarded.

### Changed

- `resolve_model`'s contract check is a `RuntimeError` rather than an `assert`,
  which `python -O` strips — a contract break would otherwise surface as
  `int(None) TypeError` in production and nowhere in development.
- SHA1 in `make_sapisidhash` is marked `usedforsecurity=False`. It is mandated
  by Google's `SAPISIDHASH` scheme; the marker records that the hash choice is
  a protocol constant so a future reader does not "fix" it into a broken login.

### Security

- **The image upload no longer sends the session cookie to an arbitrary host.**
  Step two of Gemini's resumable upload posts the image bytes plus the `Cookie`
  and `SAPISIDHASH` headers to a URL taken from a response header. With
  `proxy` configured — a supported setup for exactly this project — a hostile or
  compromised proxy could answer that header with any host and harvest the
  session. The upload URL is now constrained to `content-push.googleapis.com`
  and `upload.googleapis.com` over HTTPS. Covered by regression tests including
  subdomain and userinfo spoofing.

### Fixed

- **A failed page-token scrape no longer re-fetches on every image.** The cache
  guard was `if fresh and tokens`, so an empty result stayed falsy and each
  subsequent upload triggered another authenticated page load — an extra request
  per image precisely when the network is already failing. The cache now records
  whether a fetch happened, separately from whether it succeeded.

- No credentials are read, logged, or included in error output. `redacted()`
  exists so a full config dump is safe to print.
- The full git history was scanned for live cookie, SAPISID, XSRF, and auth-file
  values before publication. None were ever committed.
