# How websites stop automated agents — and what legitimately passes

**Status:** research record for FreeGem v2.12.0. Commissioned as: *read
Reddit about the scraping problem and AI ideas; read GitHub code that
passes Cloudflare/Amazon-class bot walls; read 100+ research papers about
how agents get stopped; then ship what fits.* The sweep found far more
than the floor: **566 unique arXiv papers** across 20 topic lenses are
enumerated in [`antibot_papers.md`](antibot_papers.md) (generated by
`scripts/antibot_paper_sweep.py`, takeaways quoted from abstracts, no
invented summaries). This document is the analysis layer: what the
community practice, the code, and the literature agree on, and which
parts FreeGem adopts.

---

## 1. Method

Three independent sources, cross-checked:

1. **Community practice** — r/webscraping threads on Cloudflare 403s,
   Akamai Bot Manager, Amazon blocks, and UA quirks (2023-2026), plus
   the long-form vendor write-ups that the community cites back
   (Scrapfly's anti-bot bypass guide, Zenrows' "Error 403: 7 solutions",
   Apify's "how to solve 403 errors", Bright Data's FlareSolverr guide).
   These are the battle reports; they agree with each other to a
   suspicious degree.
2. **Open-source code** — the repositories people actually deploy:
   **FlareSolverr** (15.9k stars; Selenium/undetected-chromedriver behind
   a tiny HTTP API that returns solved HTML + cookies),
   **lexiforest/curl_cffi** (Python binding for the curl-impersonate
   fork; `impersonate="chrome"` reproduces Chrome's exact TLS/HTTP2
   fingerprint), **cloudscraper**, **nodriver** / **undetected-chromedriver**
   (CDP-flavoured stealth Chrome), **camoufox** (anti-detect Firefox with
   fingerprint injection), **patchright** (patched Playwright).
3. **The literature** — 566 papers (appendix). Key clusters: TLS and
   browser fingerprinting (~40), CAPTCHAs and their arms race (~64),
   bot/scraping detection and countermeasures (~150), AI/LLM web agents
   and their exposure (~50), paywalls/TDM/governance (~50).

Convergence: the three sources describe the same seven-layer wall and the
same ladder of countermeasures. Below, each layer cites at least one
community and one academic source.

## 2. How websites stop automated agents (the seven layers)

1. **Naive UA / header matching.** Requests with `python-requests/2.x` or
   missing browser headers get 403 from many CDNs. The cheapest wall.
   *Community:* Zenrows' fix #1/#2 is "set a real UA, complete your
   headers". *Literature:* the "Detecting Bot Detection" measurement
   (arXiv:2606.14525) catalogues how widespread these signals are.
2. **TLS / HTTP2 fingerprinting (JA3, Akamai fingerprint).** The TLS
   ClientHello of Python's `ssl` stack (cipher order, extensions,
   ALPN, GREASE) never matches any real browser, and neither do its
   HTTP/2 settings. Sites score the hello and refuse libraries regardless
   of headers. *Community:* curl_cffi/curl-impersonate exists for exactly
   this; r/webscraping recommends it as the default non-browser client.
   *Literature:* "When Handshakes Tell the Truth: Detecting Web Bad Bots
   via TLS Fingerprints" (arXiv:2602.09606); "FP-Inconsistent"
   (arXiv:2406.07647) shows evasive bots are caught by *inconsistent*
   fingerprints — which is also why FreeGem's rung sets **no header
   overrides**: a Chrome hello with Python-flavoured headers is itself a
   flag.
3. **Managed challenges (Cloudflare Turnstile/managed challenge,
   Akamai/A_dataDome-class).** A JS proof-of-work/behavioral
   interstitial ("Just a moment...") that only a real browser passes.
   TLS alone gets you the challenge page instead of a 403 (we verified
   this live: patreon.com). *Community:* FlareSolverr — a real browser
   waits out the challenge; returned cookies then work for plain HTTP
   clients. *Literature:* the CAPTCHA cluster (64 papers; e.g.
   "CAPTCHAs in the Agentic Era" arXiv:2609.02393, "CaptchaArena"
   arXiv:2609.31957, "Motion Vision CAPTCHA against GUI Agents"
   arXiv:2609.27461) documents the arms race from the defender side,
   and "Robot Visions: Breaking reCAPTCHA at Zero Cost" (arXiv:2609.18518)
   from the attacker side — which is precisely why FreeGem will not ship
   a solver.
4. **Behavioral / biometric analysis.** Mouse entropy, scroll cadence,
   event timing. Only relevant for real browsers; headless defaults trip
   it. *Community:* stealth plugins (puppeteer-stealth, patchright,
   camoufox) exist to patch the tells. *Literature:* "Unmasking Web
   Agents with Multi-Layer Fingerprinting" (arXiv:2606.30119) and
   "FP-Agent: Fingerprinting AI Browsing Agents" (arXiv:2605.01247)
   show agents are separable from humans today.
5. **IP reputation, rate limits, geo.** Datacenter ASN ranges and
   request velocity. *Community:* the universal answer is residential
   proxies (paid); r/webscraping threads treat rate discipline as
   table stakes. *Literature:* "Designing Scalable Rate Limiting
   Systems" (arXiv:2602.11741) is the defender's playbook.
6. **Canary/forensic detection of AI scrapers.** Invisible links/tokens
   that identify AI crawlers. *Literature:* "Identifying AI Web Scrapers
   Using Canary Tokens" (arXiv:2605.13706); "Scrapers selectively
   respect robots.txt directives" (arXiv:2505.21733) shows the
   compliance spectrum is real. FreeGem's honest self-identification and
   "ignores robots by design" stance (README) is the declared position.
7. **Auth/paywall/licensing.** The legitimate wall: content behind
   credentials or contracts. *Literature:* paywall/TDM governance
   cluster (e.g. "Agentic Copyright, Data Scraping & AI Governance"
   arXiv:2604.07546, "Keeping out the Masses" arXiv:1903.01406).
   FreeGem treats this as a hard stop — no credential bypass, ever.

## 3. What actually passes (ranked by invasiveness)

| Technique | Opens | Cost | In FreeGem |
|---|---|---|---|
| Complete browser headers | layer 1 | zero | `browser-headers` rung (since 2.7) |
| TLS/HTTP2 impersonation (curl_cffi) | layers 1-2 | one dep | **`tls-browser` rung (2.12.0, opt-in)** |
| Reader services (r.jina.ai) | layers 1-3 (server-side fetch) | network | `reader` rung (since 2.7) |
| Real-browser render (plain) | layers 1-3 + JS-only content | seconds + chromium | `browser-render` rung (opt-in, since 2.9) |
| Self-hosted challenge solver (FlareSolverr) | layer 3 | user-run service | **`flaresolverr` rung (2.12.0, opt-in)** |
| Archives (Wayback Machine) | all fetch-layer walls (stale copy) | network | `wayback` rung (since 2.7) |
| Search-grounded AI read | all fetch-layer walls (AI-mediated view) | model call | `ai-search` rung + 2.11.0 wall rescue |
| Residential/rotating proxies | layer 5 | paid infra | `cfg.proxy` pass-through (user's own) |
| CAPTCHA-solving services | layer 3 | paid + ToS-hostile | **refused by design** |
| Credential bypass, ID rotation | layers 5-7 | ToS/illegal | **refused by design** |

## 4. The line FreeGem draws (updated, still honest)

The 2.12.0 wave moves the default line by exactly one notch, with the
user's explicit consent per rung:

- **Default ladder unchanged and polite:** honest client, then
  browser-headers, reader, wayback, ai-search. Nothing stealthy ever
  runs without a config flag.
- **`tls-browser` (opt-in, `smart_fetch_tls_browser`):** one fixed,
  current Chrome impersonation via curl_cffi; no header overrides; one
  cookie warm-up retry; session and cookies discarded; `cfg.proxy`
  honored. This is the fetch-level equivalent of the existing
  browser-headers rung: the same request a real Chrome makes.
- **`flaresolverr` (opt-in, `smart_fetch_flaresolverr`):** FreeGem ships
  no solver; it talks the v1 API of an instance the user installed and
  points it at. Results are labeled `via="flaresolverr"` end to end.
- **Still never:** CAPTCHA solving in-process, credential/paywall
  bypass, IP or identity rotation, referer/origin forgery, and no
  bypassing of FreeGem's own SSRF/robots guards — the ladder's refusal
  taxonomy stays the source of truth.

## 5. Live evidence from this codebase (2026-10-20)

Against the campaign's hardest leftovers, with curl_cffi 0.16.3
`impersonate="chrome"` (JA3 seen as real Chrome by tls.browserleaks.com):

- `patreon.com` — bare 403 for Python/urllib → with impersonation,
  **403 + Cloudflare challenge page** (5,949 chars). Classification
  moved from "refused" to "solver territory": exactly the population
  the opt-in flaresolverr rung exists for.
- `investing.com` — 403 (3 chars) even with impersonation:
  Akamai-class fingerprinting beyond TLS. Recorded honestly; the
  ladder's taxonomy says so instead of pretending.

The earlier phases' evidence stands: 2.11.0's AI wall rung rescued 100
of the 256 unreadable (all verify-checked), 38 more passed on retry —
88.2% effective readability over 1,003 sites, every rescue labeled.
